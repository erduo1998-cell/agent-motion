# Motion Craft

本项目使用此本地版本与 Three.js 制作环境，不由同名全局 Skill 替代。保留作者的构思能力、用户指定的风格与修订范围；完整影片以实际内容、画面、连续动作和声音成立为交付依据。

每个新片在独立工作目录保存输入、分析、工程与输出；续作和局部修订沿用用户指定的当前工程及合格资产。用户明确要求独立复测时，从本次提供的原视频、SRT、明确参考和当前规则重新创作，不读取其他轮次的工程、成片、分析、抠像缓存或历史对话，也不向其他任务索取旧答案；相同输入不自动视为续作。公共字体、通用数学工具与有权使用的参考可用。

## 规则的适用边界

本次用户明确要求及有效修订优先，其次执行本项目对应任务的具体要求，再用通用设计方法选择实现。参考片、教程示例和旧片临时豁免不能取消当前要求。“默认”表示用户未明确改变时必须执行，不能由作者以风格判断自行省略。颜色、字体、形状和动作可按内容选择；是否落实人物描边、保护必读信息、完整读取阶段规则和完成交付检查，不属于自由选项。

真人口播包装仍须准备同步独立人物层；抠像与显示描边是两项独立决定。**保留人物原视频背景时禁止人物描边；替换人物身后原背景时必须制作清楚、宽而舒展的风格化描边。** 全幅或小窗按同一背景条件判断，不能因缩窗就自动描人。具体的换背景、局部出框与过渡判定统一见 [人物规则](../srt-reference-to-three/references/talking-head-lessons.md#参考分工与人物层)。人物视频缩成卡片后，必须有可见的3D悬浮层次，并对框内人物重新居中取景；容器居中不等于人物居中。对应实现见 [空间与镜头](references/space-camera.md) 和 [容器与内部取景](references/talking-head-motion-patterns.md#m02-将轮廓变化内部取景与容器移动分开)。只修声音等局部任务不追溯重做无关画面。

本项目设计以空间组织画面：明确前景、主焦点与背景的前后关系，通过遮挡、尺度、光影、清晰度及运动让关系可见；不能把成片做成所有元素等清晰、等权重地贴在一个平面上。二维素材与正交实现仍可使用，但必须落实所需的空间层次。新设计的字体须扩展候选并在完整构图中实际比较，按 [字体组合与海报](references/typography-poster-pairings.md) 执行，不能直接接受默认字体。

## 先接收制作输入

涉及 SRT 或真人口播时，先由本地 [SRT Skill](../srt-reference-to-three/SKILL.md) 完成内容分析。进入制作前，完整读取其实际产物，并核对原 SRT、原片/声音路径及用户最新要求；不能只凭上轮聊天摘要开工。已有 `PLAN.md`、`timeline.json` 或内容初审等合格产物直接承接，不重新造一份。纯动画接收用户 brief、真实文案与素材，不强制制造 SRT。

## 阶段前完整读取，完成后进入下一阶段

新制完整影片按下表推进。**每阶段动手前，完整读完该阶段全部页及已由任务确定的技术模块；不能只看目录、开头或每板块几段就开始做。** 对应细则从首次制作即生效，不以用户纠错为触发。读取与制作交替，不先把后续所有阶段灌入上下文。

| 阶段 | 完整读取的板块 | 本阶段完成什么 |
| --- | --- | --- |
| `assets` 素材与人物 | 任务边界、素材语义/真实性、原景保留、同步抠像、人物轮廓/描边/容器/取景、工程基础 | 准备真实资产、同步人物层与可用工程；按是否更换人物原背景决定描边开关，解决源边并准备小窗二次构图 |
| `composition` 场面与文字排版 | 主题与空间、开场、字体及中英混排、可读性、安全区、原景衬光、前后状态、阅读时间与声音条件 | 确定全片视觉方向与文字角色；在开场、最难关系段的完整画面里比较字体和关键构图，预留连续动作；不先排完整片静态页 |
| `animation` 动画、镜头与衔接 | 动作重量/时长/曲线、群体编舞、人物窗口变化、同画布推进、镜头、转场、数据演变及绝对时间 | 先做通开场及最难关系段的连续动态，再逐语义段完成构图、动作与相邻衔接，扩展至全片 |
| `sound` 声音制作 | 语义锚点、声音覆盖/力度/音色、动作声、混音及原声保护 | 按原声或音乐条件完成声音；明确无声的任务按其要求处理 |
| `review` 整片检查与交付 | 全文与回调、人物、排版、镜头转场、音画、真实输出范围和版本入口 | 先自行检查与修复，再交付完整影片及真实验证范围 |

这些是单一作者的制作阶段，不是把影片切给不同作者。composition 的完成条件是视觉方向、文字系统和代表性关键构图成立；不要求其余每段先排成定稿。随后完整读完 animation 全部页及适用模块，才开始正式动画编排；不能读第一页就写整片动画，再补读余页。开场与最难关系可以属于同一连续段，按实际内容选择。样段必须包含揭示、阅读和接入相邻内容的过程；修好后再扩展，不能只凭静帧或导出成功扩展。每个后续语义段把构图、运动和衔接一起完成，沿用已完整读取的排版规则，禁止整片套统一整页滑入/淡入函数。原声的语义时点从输入起约束画面，音乐主导任务也从构图起服从真实节奏，声音阶段负责实际制作与混合。此过程不增加用户审批或阶段记录。

## 用分页入口完整读取原文

从项目根执行：

```sh
node scripts/read-stage.mjs --stage assets --kind talking-head
```

纯动画用 `--kind animation`。脚本按 [阶段来源清单](references/stage-reading.json) 返回原文件的完整正文/完整章节，单页不超过 2200 个正文字符，保留来源和页码；它不是规则摘要。清单会检查两个 Skill 的所有参考章节，新增/改名章节未分配时明确报错，不静默漏读。

- 每次工具调用只输出一页；执行返回的 `NEXT_READ`，直到看到 `END_READING`。不要在一个工具调用里循环打印全部页，也不要混入源码、目录、图片数据或探测 JSON。建议单次工具输出预算至少 4000 token，并给外层工具同等空间；字符上限不是精确 token 估计。
- `END_PAGE` 或 `END_READING` 缺失，或工具报告截断/失败，就重读该页并补齐，不能开始制作。下一页携带源哈希；资料中途变化时从当前阶段重读，避免新旧版本混合。
- 页面完整到达后执行本阶段工作。脚本末页给出完成工作后的下一阶段命令，继续执行，不等待用户逐阶段提醒或审批；用户明确要求先审某阶段时遵守。
- 每个制作阶段动手前对照 `--list` 的任务/实现触发条件，找齐本阶段适用模块。任务已经确定要使用某项实现时，在动手前用 `--module 名称` 完整读取对应模块，模块名称与触发条件见 `--list`。例如使用 Three.js 构图适配器前读 `three-framing`；拖拽、裁切揭示、选择等互动读 `ui-interaction`，制作实体 UI 表面另读 `ui-surface`。这些是实现依赖，不是出错后的补救入口。
- SRT 产物或选定样板分析较长时可用 `--file 文件路径` 分页完整读取。参考索引用于查找，选中的案例要完整读取分析并实际查看相应连续动作，不能把搜索结果当已读案例。

参考内跨文件链接标明出处，由当前阶段清单落实；不要跟随旧入口的概述递归预读后续阶段。已有参考中“触发/修复”的措辞用于解释适用情境；归入当前阶段的规则仍须全部读完。用户授权的局部修改从受影响阶段进入，完整读该阶段对应内容并检查邻接影响；只改声音沿用已确认画面。禁止借局部修订扩大为整片重做。

## 上下文与执行边界

阶段间直接沿用 SRT 产物、当前源码、资产与预览，不新增阶段打卡、设计决定表或检查台账。已由阶段清单读完整的来源不用为了追链接反复读整文件；下一阶段清单要求的内容仍完整读取。

分页解决输出截断，阶段安排减少提前读取和重复输入；**它不会删除已占用的上下文，也不保证长片能在单窗口完成。** 若发生平台上下文压缩，从已有分析产物、工程与最近预览恢复当前工作位置；不能确认当前阶段读完整时重读该阶段，不能把压缩摘要当规则原文。无需重读全部历史对话或重启已完成制作。

脚本仅提供完整、可定位的读取顺序，不是后台制作调度器；读取完成也不等于动作或画面合格。按 review 阶段检查实际交付版本，修复原景误描边、换背景漏描边、卡片贴底、人物裁切失当、文字压盖和重复翻页式动画等已发现的问题。未完成必要观看/试听时，只能标明待检查预览及具体缺口，不能用一句限制说明把它宣布为完成成片；用户明确要求未经检查的原稿时按该范围交付原稿。

版本来源见 [安装记录](../../motion-craft-install.json)；原有制作原则按章节纳入 [制作原则](references/production-foundations.md)，不是另一个需要全量预读的入口。

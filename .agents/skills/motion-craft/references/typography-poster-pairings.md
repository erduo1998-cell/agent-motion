## 先把字体当成设计决策

当前问题不是“黑体不能用”，而是没有为内容选择字形，最后所有片子都落在默认字族、默认粗细、同一宽度和标题位置。先定义文字角色和语气，再用真实文案比较字形：新闻判断需要强而清楚的重音，引用需要与叙述区分，亲切话题需要更松的节奏，书写情绪需要笔势，数据需要稳定数字和单位。选字必须能解释它如何服务这句话。

每片在现有工程的字体配置与排版中固定一套文字系统：主标题、正文/条件、英文/数字、少量特殊重音，不另建字体决策表。显示字、说明字与数字按各自角色选家族；不能先用“一套默认中文已经够用”结束探索。允许把不同字体融合进同一系统，差异用于标题气质、引用、数据和说明，不能每镜随机换字。不是必须恰好两个字族，也不是每个镜头随机换一组。整个影片继承字体文件、字重范围、语言版本、角色与禁止替代规则；段落可以变布局，不随意更换字族。确有语义身份切换时，让不同文字角色在工程中明确对应。字体组合不要求增加英文副题或拆散完整判断句；画面主角与阅读顺序优先，辅助文字不能挤小需要看的证据或主体。

新设计在 composition 阶段先以真实内容试排至少两个有实质差异的方向，例如特黑叠排与粗宋留白，而不是同一黑体的两个字号。比较对象必须是完整构图：放入本段实际需要的人物、按背景条件出现的描边、主标题、正文/条件、数字单位和素材/卡片，纯动画不因此增加人物；每个方向按自身字形重新调整分行、比例、对齐、行距与留白，不能只在同一空白区域替换两个 font-family。覆盖开场及信息最密的代表状态，二者重合时可共用；不为比较而先排全片，也不增加用户审图环节。用户已锁定字体或已认可的系统继承使用，只修当前问题。

**开放的新设计必须扩展显示字体候选。** 先查看本地字体库与选型样张，不能只在默认中性黑体和默认宋体之间二选一；还须实际试排具有不同字形个性的中文显示家族，例如切角/窄字面、书写、圆体或美术字中的合适方向。下表是资源起点，不是指定答案，也不能每片固定选第一项。现有候选与内容不合时继续找合适家族，核实字库与许可后再用。最终可以选黑体或宋体，但必须通过与扩展候选的完整画面比较，而非因易加载、已安装或能容纳最长句直接胜出。

试排必须渲染到本次任务的实际画幅并查看，保留本次候选画面供比较；没有渲染的方案不能写成“已比较”。每套按自身字形重排字组的轮廓、分行、图文关系与留白，不在同一模板里只换font-family。比较开场的辨识度与最密状态的可读性，再在连续样段里看运动中的字面和气质。最终字体角色落实到工程配置；缺字或回退必须修复，不得悄悄退回默认字。更多尝试发生在选型，最终家族按角色统一，不为凑数量把全片变成字体拼盘。

选择时逐项比较：字形与口播语气是否一致；主句、解释与数字是否分级；字组是否与人物/证据共同构图；最密状态的组内、组间及容器内边距是否清楚；手机尺寸是否可读。若只是无溢出却显得拥挤、字重压倒人物或正文像标题，继续修正相应构图，不能凭字体加载成功选定。黑体、宋体、书写体都按上述画面表现选择，不因题材名称或下载顺序自动选用。进入 animation 后，用选定系统检查进场、重排与衔接中的碰撞和阅读时间。

## 超大字布局的执行方法

先把当前语义写成可读组，再决定它们在画面中是什么形状。优先比较以下结构，不规定每片必须使用哪一种：

- **字组叠排**：每行承担一个完整语义作用，宽度可有差别。用真实字形调整，不把每行强行拉到一样宽。超大字占据画面时减少其他焦点，条件保留在可读区域。
- **宋黑编辑关系**：引用、判断与解释用不同笔画结构和密度分级；留白让观众知道先读哪里。不是“一宋一黑”就完成层级。
- **主字跨画幅＋小证据**：显示字可以在非关键笔画处有意出血，先验证词语仍能辨认；首次出现的人名、数字、否定词、单位不能在必要阅读时被裁掉。背景大字与前景完整可读标题须明确角色。
- **图文嵌合**：沿主体轮廓、方向或边线安排字组，允许有意义遮挡；重点阅读阶段检查每个关键字与主体身份。先调图文相对关系，不把双方整体缩小来消除冲突。
- **数字主导＋窄体说明**：数字、符号、单位组成一个稳定组，解释在同一对齐系统；先测最终位数。不能做巨大数字却让“约、至多、同比”消失。

“超大”是相对于画面与其他内容的尺度关系，不是固定字号；不同画幅重新构图。字幕安全区和原视频人物重要部位依当前片子检查，不把整个画面缩进固定小框。先看一秒能认出什么，再看留给完整读取的时间是否足够。

## 字体如何影响动画

运动单位优先是语义块、行和词组。特黑块可以有重量明确的落点，宋体需要避免细横在持续运动中糊掉，圆体可有柔和节奏，书写体保留笔势，得意黑用其字形方向而不是全屏乱斜。这些是待实片验证的设计选择，不能变成“某字体必须某缓动”的绑定模板。

大字的出场、重排和接出要发展意思。例如“复杂”被分散关系聚拢为清楚结构；只把不同句子依次淡入同一海报模板不算动态排版。阅读阶段保证必要文字稳定清楚，快闪阶段可以截取片段，但不能把论点必要部分仅留在无法读取的快帧里。整词遮罩、整行换位和主体交接均可使用；真实逐笔、3D 挤出或形变需要对应实现证据。

## 最小而真实的字体检查

1. 从本地字体文件读 `cmap`，对本片每条实际 run 做缺字检查；样张脚本 `make-specimens.py` 共核验 39 条 run，均覆盖。`verify-fonts.py '本片实际文字'` 可输出各文件缺字。`coverage-probe.json` 特意保留粉圆简体缺字和拉丁字体不覆盖中文的结果，**不能把非空缺字列表忽略为通过**。
2. Web 中显式 `@font-face`，变量字体指定范围。Noto Sans SC 文件默认轴值 100、Serif SC 默认 200，如果 CSS 声明错，会落在细字，恰是“字体看起来默认”的一种原因。声明 `font-synthesis:none`，不用伪粗假装存在字重。
3. 渲染前 `await document.fonts.load('900 100px "FilmSans"', actualText)`，确认返回对应 face 且 loaded，再 `document.fonts.ready`。单独 `document.fonts.check()` 不能证明某字符由指定文件绘出；必须结合 cmap、face 加载和真实截图。
4. DOM、Canvas 与 Three.js 纹理分别验证：Canvas 要在字体加载后测量/绘制，缓存文字纹理须由字体版本、字重、文本、像素比共同区分；字体加载前绘制的旧纹理必须重建。变量字体用于几何字形转换时明确工具是否支持轴实例，不能把最细默认轴当 900；不支持则用合规实例化/已核验静态字体并保留许可。
5. 字幕/标题定稿后，在交付尺寸与缩小预览中检查字面、基线、笔画、断行、字间碰撞、符号单位和语言混排。再正常速度检查出场、稳定阅读和接出。程序通过、静帧通过、连续播放通过是三种不同证据。

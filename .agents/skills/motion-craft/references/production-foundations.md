# Motion Craft 制作原则

本文件保存原正式入口中的制作原则；由 `stage-reading.json` 按章节安排在对应阶段完整读取。文中链接用于标明规则出处；“读某文件”由当前阶段清单落实，不从这里递归整包读取其他阶段。旧流程概述保留制作原则，执行顺序以两个当前 SKILL.md 为准。不能等用户指出问题才补读细则；文中计划、记录均复用上游分析和工程，不新增阶段设计/检查表。

用自己的创作能力决定片子的气质、视觉意象和节奏。这个 Skill 帮你将决定落实并辨别效果，不指定一种好看的版式、色板、镜头数量或装饰密度。完成的是一段值得看、能理解、细节经得住看的影片。

## 本项目使用与交接

本项目使用当前本地版本，在本次独立目录建立 Three.js 场景、素材与渲染流程；同名全局 Skill 不替代本版本。具体风格与任务范围以用户当前要求和参考为准。版本来源与本地修订记录见 [安装记录](../../../motion-craft-install.json)。

当前完整影片由同一作者持续制作，不启用已撤销的多 Agent 分段方案。只有本次用户明确授权的辅助委派才交给子 Agent，并提供本地 Skill 路径、用户原始要求、当前素材与最新范围；所用参考同步交接，让执行者读取同一版本。涉及 SRT、真人口播或参考驱动制作时，同时提供本地 [SRT 制作 Skill](../../srt-reference-to-three/SKILL.md)。

## 先接住真实任务

区分用户明确要求与自己的实现选择。真实三维、连续交互、快闪、中文主标题、品牌文案、声音条件等要求不能在交接时降格成可选项；用户允许二维时也不强迫使用三维。接口、时长和帧率是工程合同，不是本片创意。

先看项目实际资产与可用实现。原品牌使用真实素材；原创内容可以自制。不要在没有照片的项目里假设摄影资产会补齐质感，也不要因为能写几何体就把有机物、光、纸和金属都画成相同的硬形状。

需要参考时，读 [内容与画面](../references/content-to-picture.md)。从参考中拿走对象关系、取景理由或动作因果；保留本片的字句、材料和视觉语言。用户提供了成片或可运行参考时，实际看其画面或运行其局部，不能只读介绍就声称学到了效果。

本项目新制影片、开场或设计页面时，按 [参考与素材](../../srt-reference-to-three/references/reference-and-assets.md) 默认从公开参考分析库选择本片相关机制，用户当前参考优先。完整读取所选报告，在现有设计记录中写明案例标识、适用的源时间、借用机制和内容适配；读分析结果不等于本次已观看动态。需要复刻或核对具体参考动态时，按该入口实际查看有权访问的原参考及连续证据。原视频不随开源包分发，也不是读取分析结果的前提。案例中的颜色、人物、文案和时长不直接变成模板。纯文案或声音修订沿用已确认设计，不为了查库扩大范围。

重新设计视觉段落同样执行上述查库与回看。样板用于配色职责、视觉重心、空间、镜头、转场和页面状态的选择，不是统一风格或必须集齐的效果清单；不要求通读全部案例。报告中的实际观察与 Three.js 实施建议分开判断，后者尚非已验证组件，必须用本片输出验证。

## 把想法变成能判断的东西

先明确这一段要让人看见什么、经历什么。composition 阶段确定全片方向，并用开场和最难关系段建立代表性关键构图；重要状态用真实字体、真实文案、真实对象与交付相机组成，不把它们藏在入场动画的 opacity=0 后面再凭数字猜终点。这里不要求先完成全片静态排版，正式动画编排必须等 animation 全部规则读完。

针对一段片子，保留一个自己想实现的观看结果，并辨别最可能让它失败的关系。例如：观众应看懂所选内容展开了，还是只看到了两个界面交替？这一句用来判断自己的作品，不必变成用户看见的流程表。

按影片类型选能暴露问题的试做对象：快闪先做一段有视觉节拍变化的连续短段，UI先做从一次输入到结果的完整交接，产品先做能辨认其材料与轮廓的镜位变化。关键静帧只回答构图，不能单独回答类型是否成立。读 [语义章节与视觉节拍](../references/film-grammar.md)，避免把每段文案自动变成一张长停留的海报。

阅读 [如何根据画面作决定](../references/visual-decisions.md)，把观察落到自己的输出。允许预览时，先取得关键状态与连接过程的可见证据，再扩展次要细节。用项目已有截图、渲染、播放器或逐帧工具；不要只运行语法检查后提交。

## 各类画面的实现要求

- **中英排版与画面层级**：读 [动态排版](../references/typography-cjk-latin.md)。需要选字体、改善默认字形或设计海报大字时，同时读 [字体组合与海报](../references/typography-poster-pairings.md)，以实际文案比较字形和角色。一起安排中文重音、补充语、英文品牌和图形主体；它们在实际字形、观看尺寸和阅读窗口中的关系比名义字号更重要。大字可以压图，但文字需要读、产品标识也需要认的时候，应设计两者同时成立的画面。短视频安全区、资料密度、数字遮挡或无动机倾斜问题同时读 [排版与可读性](../references/layout.md)：满幅构图只让重要内容避挡，不能整体缩小代替重排。
- **场面与三维材料**：读 [把空间和材料落实](../references/implementation-choices.md)。镜头必须真正作用于需要展示的物体，表面与光要产生所需的可见线索；给背景加 Three.js 不会让前面的 DOM 界面自动变成三维实体。先让主体和一个有用的环境关系成立，再判断细节该加在哪里。
- **连续 UI 与转场**：读 [转场实现](../references/transition-construction.md) 及 [实现选择](../references/implementation-choices.md) 的对象交接部分。由同一次状态变化驱动指针、目标反馈、对象移动和结果。让旧布局退出、新布局接管，保留可跟随的对象；不要让多套副本各自淡化后碰巧叠在一起。
- **口播容器与交互包装**：出现全幅人物变窗、身后标题、拖拽揭示、缩略图选择或固定框轮播时，读 [容器、遮罩与动作因果](../references/talking-head-motion-patterns.md)。先定可读终态，人物小窗必须有3D悬浮并以真实人物重新居中取景；分别控制容器、遮罩与内部视频，按背景条件决定人物描边，将边界和揭示绑定为同一动作，检查人物交接的中间帧。教程配色、卡片数、倍速与软件操作不作为固定制作参数。
- **整片节奏**：读 [整体节奏](../references/sequence-rhythm.md)。围绕内容组织快慢、重音、停顿和变化；没有音乐就以动作和阅读构成节奏，不能把空白留给不存在的配乐。快闪的视觉变化、说明片的阅读时间和真实操作的反馈时机各有依据。

可以用实际投影帮你实现三维取景：已有 [取景适配器](../references/three-framing-adapter.md)；只需检查屏幕占位时可用 scripts/project-bounds.mjs。这些工具提供位置证据，不决定构图，也不把所有遮挡都判为错误。

## 让作者完成制作

把构思、实现和自己的实际输出连起来。改动前说明可见症状与原因，选择能改变该关系的处理；改动后看同一状态及相邻动作，确认问题消失且没有损害画面气质。按影响大小修最关键的问题，再决定是否需要下一次修改。无需为了流程重写已经成立的部分。

复刻动效参考时，先还原运动关系，再精修造型材质。必须逐段区分相机平移/推拉/绕转/滚转、物体变换与焦点变化，记录起止取景、运动方向、速度峰值和停稳时机；不能用整体缩放或旋转物体冒充原片的运镜。快速段检查源帧率附近的连续帧，并在同一时间轴比较原片与复刻。运动模糊应随曝光期间真实投影位移产生，静止段清晰，硬切不混帧；景深与运动模糊分别检验。原片没有大幅运镜时不凭空增加环绕。仅凭成片无法唯一恢复的相机参数，应注明拟合选择，不声称精确反解。

逐帧复刻先读取原片实际帧率，按原生帧率解码完整目标动作或循环，不用默认 30 fps 解释 24 fps 素材。给短促事件记录零基帧号与相邻状态：闪黑/亮帧、屏内原文及逐词变化、厚度与遮挡、形变连接/断开/回缩、内部动态和人体姿势。逐帧联系表只作全段索引，关键细节还要查看足够分辨率的源帧，并与同帧渲染输出比较；发现画幅占比、文本时机、模型轮廓、色彩光比的差异也要记录和处理。实现了同类效果不能替代相似度验收，替代模型或未解差异必须明确标注，不能把粗略造型作为已完成复刻。

制作不应停在“做了圆角、设置了景深、使用了缓动”。圆角要在交付机位读得出边缘，景深要分离该分离的内容，缓动组合后要形成所需的动作。所用引擎或参数不是完成证据。

用户要求原稿、不准预览或修改时遵守该范围，保留真实首稿；此时不要宣称完成了视觉修复或正常生产验收。允许制作修订时，保留可比较的前后版本，依据实际缺陷修改，不反复抽新方案赌随机结果。

最终交付完成检查的完整影片。正常速度的观看判断、转场帧序列、单帧细节、代码与测量分别说明了什么，就按实际范围报告；工具只能提供抽帧时不能冒称已完整观影。完整输出存在、必需内容正确、主要观看关系成立，三者都要落实。必要观看/试听未完成时，按 [验证规则](verification.md) 标为待检查预览；限制说明不能代替未做的检查，也不能掩盖已发现而未修复的问题。

可按需深入 [动作与重量](../references/motion.md)、[场面与镜头](../references/film-direction.md)、[跨引擎实现](../references/engine-mapping.md)。不要用阅读更多资料代替当前画面的实现和判断。

# 从观看关系选择实现

## 文字和三维主体要一起排

屏幕层文字与三维相机各自写一组位置数值，不能保证合成后协调。确定主状态时把二者放进同一交付画面。产品标识需要识别的时段，可以投影该标识所在部件的实际范围，再判断标题是否争用它；不是只看物体中心点，也不是保护整个画面不许遮挡。

scripts/project-bounds.mjs 提供 Three.js 对象世界包围盒投影到画面后的矩形。它适合定位与排查，不等于像素轮廓：透明纹理、非矩形对象和复杂遮罩仍需看实际图像。AE 用图层 sourceRect 与合成坐标，Blender 用交付相机投影实现同样的观察。

## 连续交互的状态要统一

先有用户动作和内容身份，再决定图层。选择项、展开中的对象、详情主体可以共用一个对象，在容器内重排内容；需要代理时，把交接看作明确的所有权转换：什么时刻由谁显示，二者的视觉状态如何对应，旧背景何时退场。

点击位置来自当前实际按钮或被选对象的位置，不来自另一条猜测的光标路径。按下、释放、加载或播放，是同一事件的不同阶段。若设计表达轻触后自动展开，光标可以离开；表达拖拽时应持续维持接触关系。不要把交互做成任意位置上的装饰波纹。

对于真实三维 UI，承载内容的面、边缘或部件要存在于受相机与光影响的场景中。可将经过排版的 UI 渲染为高分辨率纹理，贴到有合理边缘的实体表面；将需要独立操作的部件单独建层；或使用引擎原生文字与面板。纹理含字时，任意拉宽整个面会扭曲文字，布局变化需要重新排版。屏幕叠加层适合片外字幕和说明，不自动承担实体界面。

需要现成的技术连接时，可读 [UI 表面适配器](ui-surface-adapter.md)：提供内容绘制、实体承载、布局更新与控件坐标映射，界面样式和构图由你创作。主界面的字、控件与背景面应共用空间关系；只将其中的按钮或装饰建模，不能让其余浮在屏幕上的内容获得实体连续性。

## 让材料有能被识别的线索

先看轮廓与表面：接缝、口沿、倒角、层叠厚度、微小凹凸是否承担物体身份，再看主光、环境反射与接触关系。只把 metalness 设为 1、roughness 调低，不能凭空得到合适的摄影光线；没有环境结构的反射仍可能是一大片灰。

属于物体表面的图形要服从承载面的曲率和受光。曲面上的印刷可用宿主 UV、曲面贴片或 decal；把一张宽平面放在圆柱最前方，会让两侧悬空，近看时像另加的牌子。不同表面工艺可以具有不同粗糙度，但普通印刷不会像自发光屏幕一样完全无视场景光线。检查侧视与近看，确认构造符合你要表达的材料。

需要较软的边缘高光时，要有能接光的曲面或倒角，也要有足够宽的光源或环境明暗变化。接触影、反射、细微粗糙差异应服从材质与尺度，不能用强光晕一概盖住。景深只在需要分开前后层时使用，检查文字和目标有没有一起失焦；背景仍有亮斑抢眼时，仅增加虚化未必有效。

光束、雾、液体和半透明固体有不同的轮廓。透明锥体使用常量透明度，仍会显出锥体的硬边；如果目标是散射光，需要体积、软化的密度场或基于视角与距离衰减的近似。先看该实现是否读成光，再决定是否增加粒子。图解风格可以保留几何光束，但不能把这种图解误称为自然体积光。

## 参考如何变成能力

使用可运行参考时，先辨别它解决的是哪个关系。把点击与目标绑定、把两种布局用同一对象交接、给表面构造反射环境等实现，可以在新的品牌与风格中复用。不要顺带继承示例的固定文案、角标、字体或版式。找不到匹配实现时，先做能看见差异的小段，再扩展；不靠文件名或文档描述认定效果已经成立。

# 制作记录与执行

用于将内容计划落实成可续作的 Three.js 工程与实际视频。这里是编写和交接约定，不是已经存在的自动编译器或 H3 schema。

## 只记录会影响制作的内容

沿用当前任务的 `timeline.json`、分析说明或其他已有计划；没有时在该任务目录建立一份精简计划。机器读取的字段保持稳定，人看的说明解释设计理由；不为相同信息维护多份必须手动同步的表。

开场作为第一组语义单元，在同一计划中写清主图、主题标题、图字层级、揭示动作和接正文的方式。它占用实际开头口播的时间，不默认在原片前另插一段静态标题或延长成片。

全片记录输入路径、目标画幅/帧率/时长依据、声音处理、内容结构、参考用途和用户限制。每个语义单元至少能找回：

| 信息 | 制作用途 |
| --- | --- |
| ID、原片起止时间、SRT 关联及原话 | 追溯内容；区分源时间和段内时间 |
| 表达目的、重点文字及必要条件 | 避免画面只贴标签或改错原意 |
| 主体、素材及来源、画面层级 | 确认真实资产与可实施布局 |
| 起始状态、动作、结果、阅读落点 | 驱动动画，不只列静态画面 |
| 入出方式与连续对象 | 连接相邻段落与原片 |
| 样板案例 ID、源时间段、借用机制与本片改造 | 让参考选择落实到具体状态和验证落点；无关的局部修订可沿用原记录 |
| 相关声音落点与对齐依据 | 适用时连接画面、原声和音效 |

同类短视频在这份现有计划内补充适用信息：发布界面遮挡的依据或暂定假设；原片硬字幕、新增字幕与重点文字各自的处理；人物形态和切换理由；当前用户指定的水平、颜色或转场要求。有量化数据时记录准确终值、单位与图形变化；有回调时记录成员集合。不是每个镜头都填所有字段，也不新建平行表。

记录粒度服务本次任务；不强制每句填满字段，不把一个语义单元限制为一个镜头。仅改一处数字或音效时无需重建全片计划。

后续纠正记录位置、用户最终决定、被替代要求及仍待核实事项。可推广的制作要求统一写入对应 Skill 或其按需引用，并由 Skill 入口明确触发；AGENTS 只保留入口与使用关系，不并行维护另一套制作细则。回顾报告保存来源，不能替代生产规则和实际制作检查。片内文案、具体秒数、放大参数、参考配色和临时豁免留在任务。不要把内部自检写成用户验收。

## 复用实际工程

每个新片在 `work/<本片目录>/` 保存输入、素材、场景、时间线、渲染入口与输出；用户要求续作或局部修订时承接指定工程。明确的独立复测使用全新目录，只承接本次制作各阶段的产物，不读取其他任务工程或上一轮分析、抠像、布局和时间线。

新工程可提供 `window.film.ready`、`duration`、`fps` 与 `renderAt(seconds)`，通过本地服务、Playwright/Chrome 取帧并用 FFmpeg 编码。根目录只保留通用依赖和静态服务，没有默认成片或通用成片渲染命令；在本次任务内创建对应页面、渲染入口与输出路径。浏览器启动可复用根目录 `scripts/browser.mjs` 的 `launchBrowser()`；它支持 Playwright 安装的 Chromium、`BROWSER_CHANNEL` 或 `BROWSER_EXECUTABLE`，不写死某台机器的 Chrome 路径。FFmpeg/FFprobe 通过 PATH 或 `FFMPEG_PATH` / `FFPROBE_PATH` 选择；进程参数用数组传递，路径通过 Node/Python 标准库拼接。

场景与媒体由绝对时间驱动，等待纹理、字体和视频目标帧就绪后捕获。交互预览和导出共用状态计算，检查跳转、顺序播放与重复渲染的关键状态是否一致；避免依赖墙上时间或上一次 seek 留下的累积状态。

实现使用最能表达内容的层与对象。真实人物、资料和图片可作为独立平面，三维主体用相应几何与灯光，必要文字可控绘制。Three.js 是制作宿主，不意味着全部内容必须挤出成三维字，也不意味着背景存在 3D 就已实现前景的空间关系。

真人口播的前置制作必须落实主 Skill 的抠像双轨要求。工程保留原片底轨、透明人物素材或逐帧遮罩及其同步关系；镜头计划写清人物前后的包装对象、焦点与虚化关系。已有合格双轨可复用。源素材保存与最终独立轨道导出是两件事，不把“用户没要求额外交付透明 MOV”当作省略工程人物层的理由。

全幅、小窗和局部出框按 [口播规则](talking-head-lessons.md#参考分工与人物层) 判定：保留人物原背景不描边，换掉人物身后原背景才描边。缩窗另做卡片3D悬浮与框内人物二次居中构图；不能用描人替代卡片投影，也不能用居中的容器冒充人物居中。源视频材质与光照实现也需核对，避免灯光只照亮背景、人物面部完全不受影响却自报完成补光。

## 动态验证与完成

完整读完动画阶段后，内部试做必须覆盖开场和最难关系，如资料页高亮、人物跨层移动、历史资料接续或连续 UI；二者可在同一连续段中验证。检查起始、动作、稳定结果与相邻交接，修好后逐语义段扩大到整片，不先写完全片再补试做。单张终态、联系表和播放器能打开均不证明样段动态通过。

完整输出核对可解码、画幅/帧率、视频与音频时长及尾部完整性。可见验收对照实际需求检查：必需内容、准确文字、关键词顺序、阅读窗口、人物边缘和裁切、层级与转场。用户要求声音时另检查原声与音效；无声导出不能当作有声交付。

真人口播另核对：同步人物层确实存在且可独立调度；原景无人物描边，换背景区域有合格描边，卡片悬浮及人物取景成立；身后/前景遮挡正确；人物移位无底轨重影；虚化区分空间与焦点且不损害必读信息。检查连续动作，不能只凭图层清单或透明文件存在判定空间包装通过。

对本轮反复失败点做针对性检查，相关内容存在时才适用：

- **安全与排版**：叠加已知平台遮挡检查重要文字、脸部和小窗的完整运动范围；画幅仍满幅。检查真实字形与人物、标签、卡片、原页文字、数字及单位最多并存时的间距和分组。不得出现标题/注释压盖原页正文、标签紧贴人物边带、不同组挤在一起却把同组内容拉散等误读；要求水平的框在最终投影中保持水平。
- **字体与层级**：检查所选字形是否适合本片语气，主标题、条件、正文、数字是否各有角色，最密画面是否仍有明确阅读顺序。已加载、无缺字、用了 900 字重均不等于字体选对；不以“换过宋体/黑体”代替完整构图比较。
- **证据与回调**：画面说明真正的比较双方、条件与结论；高亮原文支持当前句子；总结回收前文成员，不能只剩最后一个对象。
- **数据与连续性**：看计数起势、变化、落定和阅读段，数字与图形同向且准确；跨版式看交接前、过程中与交接后连续片段。检查是否把不同语义段全做成相同整页平移、淡入或固定标题换字；必须在实际动作中看到对象关系与信息的推进。源代码有动画配置不等于输出出现了过程。
- **人物与声音**：正常速度看窗口变换是否跟随完整意群；原景段无人物装饰边，换背景段在最大/最小人物及手势峰值时边带宽而清楚；人物卡片从底面浮起，头顶/脸/颈肩不被误切、视觉中轴居中，移动中也须成立。听文字、标题、动作和情绪音效与原声的实际组合。未能试听时声音检查尚未完成，不能仅以峰值/响度证明音色合适。

这组检查是现有动态验收的重点，不增加默认用户审批或另一次全片重渲染；通过后仅因新改动、失败或明确疑点复查相应范围。

修订保留可比较版本；用户说不要对比页，只撤销额外对比界面，不表示可覆盖旧源或旧成片。局部改变不重复改写已成立的场景。纯音效修订若无需改画面可复用原视频流，既减少渲染也便于验证画面未被意外改变。

正式成片交付前，必须检查本次实际输出的完整正常速度预览；有声任务必须试听实际交付音轨，并检查上述关键帧与连续风险段。发现原景误描边、换背景漏描边、卡片无悬浮层次、人物裁切失当、压盖或动画未成立，先在当前工程修复，再检查受影响范围。导出成功不能抵消可见失败；不能把已知问题交给用户代做首次自检。

完成上述检查后，交付完整 MP4、可编辑源工程入口与简短的实际验证说明，不另建检查台账。当前工具确实无法完成必要观看/试听时，先完成能做的检查与修复，把结果明确标为“待检查预览”并指出具体缺口，不能一边写未检查一边宣布成片已完成；用户明确要求未经检查的原稿时按其范围交付。独立片段、透明人物、遮罩或剪辑交换文件按用户要求提供。只有完成对应应用导入验证时，才声称交换工程已可在该应用使用。抽帧、连续帧、正常速度观看和音频信号检查分别说明检查范围，不能相互替代。

当前交付的 manifest、播放器、源码入口和复现命令指向同一版本；既有 README 或脚本默认绑定旧画幅时显式改成本片入口，避免照旧说明误渲历史版。
